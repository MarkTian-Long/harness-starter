# 第一次使用

本套规则和辅助工具需要你选择的 AI 助手读取执行，不提供模型、账号或项目内容，也不自动接管电脑。

## 选择起点

- **整体采用作者风格**：recommended 已安装协作风格与六份按需 SOP。对助手说：“读本目录入口，采用默认协作风格，完成 task.md 的任务。”这不代表已经确认你的职业、身份或永久偏好。
- **自己调整**：在 private/overlay.md 写与默认风格不同的偏好和适用范围，例如“方案先列两种选择，再由我决定”。当前明确要求优先，选择偏好不授予操作权限。
- **最简使用**：初始化时选 minimal，只用目标、输入、完成条件和基础规则。已有目录不能用 init 切换模式或升级；比较时用另一个空目录，保留已有改动。

## 可以改什么

| 文件 | 可填写或修改的内容 |
| --- | --- |
| task.md | 本次目标、资料位置、完成条件、结果 |
| private/overlay.md | 表达和讨论偏好；不要写密钥 |
| private/profile.md（可选自行建立） | 愿意提供的个人背景、适用范围、复核条件；无需照搬作者身份 |
| profile/style.md（推荐模式） | 共享的默认风格；个人差异优先放私人配置 |
| standards/（推荐模式） | 经真实任务验证的方法；保留适用范围和退出条件 |
| recovery/checkpoint.md（如有） | 中断时已有成果、证据位置、下一步 |

private/ 是私人文件约定，Git 忽略不是访问控制。导出的私人配置按私人资料保管，不随公开核心发布。导入后重新核对旧路径、过期事实、工具依赖和权限，不继承原作者或旧环境的授权。

## 第一个真实任务

1. 在 task.md 写一个能检查结果的目标，例如“根据 workspace 内三份公开资料，比较三个笔记工具，输出一页建议并列来源”。
2. 放入必要材料，让助手读 AGENTS.md，先定位适用的已有方法后执行。只有任务出现真实缺口时再按工具采用 SOP 选单个小件；核对固定版本、依赖和授权，不整包安装。缺材料时说明未知，不假装已经获取。
3. 检查结果是否准确、有用，以及中断后能否继续。纠正不合适的表达；一次反馈不必成为永久规则。

工具检查的是文件和安装状态。任务质量、助手实际加载规则、权限与能力可用性，需要在自己的环境中验证。
