# 从两版过渡到统一核心

第一次使用公共核心只需公开源码或发行 ZIP，不需要原作者的私人迁移包。
下文的旧私人工具仅供已经持有这些历史资产的人按需评估，不是本仓库的安装依赖。

当前唯一继续演进的核心在本项目中。原 Starter 被推荐预设与私人配置能力扩展，
旧私人迁移项目保留为历史资产恢复工具，不作为第二条功能产品线继续演进。
不删除旧包、旧源码或现用配置；它们是原版本恢复和证据。

## 去向和实际覆盖

| 原来的资产 | 统一版本中的去向 | 是否自动搬迁 |
| --- | --- | --- |
| 公开 Starter 的初始化、检查、续接和退出 | 同一 starter.py，保留安全边界并扩展预设 | 新空目录初始化 |
| 私人规则中的通用协作方法 | 推荐风格与按需 SOP，去除个人身份、路径和历史授权 | 默认安装 |
| 个人画像与偏好 | private/overlay.md、private/profile.md | 明确指定私人 JSON 后导入 |
| 用户级、工作区、个人区的组织方法 | 入口、资料归位 SOP、workspace/personal 说明 | 通用方法安装；不创建公司台账 |
| 本地九套 Skills、PowerShell 检查器和第三方实现 | 保留原私人快照及来源；按需恢复或从正式来源安装 | 不随公开核心分发，也不随 profile 导出 |
| 历史任务、业务原文、聊天、账号、后台服务 | 留在原位置/相应系统 | 不迁移 |

本版并不等价于把原私人包的全部工具原样公开。
需要某项旧工具时，先读取原私人包的 DEPENDENCIES.md，按它的恢复方法隔离恢复，
完成目标机的依赖与真实调用验证；然后在当前任务按需使用。不自动复制到全局 Skills 目录。
原包验证只证明原快照，不能证明新机工具已经可用。

## 已用旧 Starter 的用户

旧版本的状态只能用匹配的旧脚本检查、退出。新版本明确拒绝旧状态，不盲目覆盖或升级。
保留旧目录，在新空目录安装统一核心；审阅后将自己的偏好填入新 private 层。
项目材料继续在原正式位置引用，不为了升级批量移动业务资料。
旧任务检查点的进度和来源需核对后再续接，不能从模板推定任务已经完成。

## 升级与回退

本版没有原位升级器。退出保留私有内容与用户修改。回退使用原目录、原脚本与原包；
不会撤销另行安装的工具、账户连接或现用 Codex 设置。
“一套版本”指核心只维护一次，私人 JSON 是数据而非另一套程序。
